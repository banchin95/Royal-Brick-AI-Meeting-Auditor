# Royal Brick AI Meeting Auditor

Flutter Web приложение для записи и анализа переговоров менеджеров с клиентами.
Бизнес-правила основаны на PDF заказчика «СИСТЕМНЫЙ ПРОМПТ — АУДИТОР ВСТРЕЧ
ROYAL BRICK» (31 страница). Подробности — в [docs/business-rules.md](docs/business-rules.md).

## Как пользоваться

1. Загрузите аудио или запишите разговор с микрофона, затем нажмите
   «Распознать аудио». Если расшифровка уже есть, выберите «У меня есть текст».
2. Проверьте текст. После распознавания ИИ автоматически предложит участников
   и роли. При необходимости измените роли в карточках и нажмите
   «Подтвердить участников». Предложенную разметку можно отменить.
3. Нажмите «Создать отчёт». В результате доступны оценка из 100 баллов,
   охват, девять критериев и 13 раскрывающихся разделов. Можно скопировать
   весь отчёт, отдельный раздел или резюме для CRM.

На экране нет деморежима, учебных примеров и переключателя разделения голосов.
Используется обычное распознавание; участники определяются по тексту.
Это смысловое предположение — проверьте распределение реплик по записи.
Обоснование ролей и предпросмотр находятся в блоке «Почему такие роли?».
Оценка запускается только после проверки участников и нажатия кнопки отчёта.

В «Дополнительно» находятся полнота записи, контекст и ручное объединение
меток. После распознавания запись считается неполной до вашей проверки.
Для уже подписанного текста используйте `Участник 1:` и `Участник 2:`;
назначьте одного менеджера и хотя бы одного клиента. Доступна также роль
«Другой участник». Метки времени необязательны. При правке входных данных
прежний отчёт убирается. Ошибки API показываются без подмены результата.

Лимит аудио: 100 МБ / 60 минут, длинные записи обрабатываются частями.
Распознавание можно отменить. Для микрофона нужен localhost или HTTPS
и разрешение браузера. Аудио и текст передаются OpenAI для обработки.
Данные встречи хранятся в памяти вкладки; «Новая встреча» очищает экран.

API-ключ хранится только в игнорируемом `backend/.env.local`.
Запуск FastAPI и настройка моделей — в [backend/README.md](backend/README.md).
Реальные аудио, расшифровки и оригинальный приватный промпт не включаются в Git.
Внутренние вымышленные примеры оставлены только для тестов расчётов.

Репозиторий: [Royal-Brick-AI-Meeting-Auditor](https://github.com/banchin95/Royal-Brick-AI-Meeting-Auditor).
После завершённых шагов изменения отправляются в `origin/master`.

## Проверка текущего шага

Упрощение интерфейса: 25 Flutter-тестов и 66 backend-тестов пройдены;
анализатор Flutter без замечаний, release-сборка Web успешна.
Проверены пустой старт, ввод своего текста, назначение и исправление ролей,
отмена разметки, скрытые настройки, 13 разделов отчёта и копирование.
Проверка интерфейса использует вымышленные данные и ответы тестового сервера.

## Запуск для разработки

Из корневой папки проекта:

```sh
python3 scripts/with_timeout.py 20 flutter --version --suppress-analytics
python3 scripts/with_timeout.py 60 flutter --suppress-analytics pub get --offline
flutter --suppress-analytics run -d chrome --no-pub --web-hostname 127.0.0.1 --web-port 8080
```

Если зависимости ещё не закэшированы, вместо `pub get --offline` выполните
`python3 scripts/with_timeout.py 90 flutter --suppress-analytics pub get`.

Сервер разработки работает до остановки: `q` в терминале или `Ctrl+C`.
Предварительно запустите backend из отдельного терминала.
Другой адрес backend задаётся через `--dart-define=API_BASE_URL=http://127.0.0.1:8000`
при `flutter run` или `flutter build web`. В этот параметр не передаются ключи.
Если запуск не завершился за две минуты, остановите команду и изучите
вывод; повторять проверку версии в цикле не нужно.

## Сборка и локальный просмотр

```sh
python3 scripts/with_timeout.py 60 flutter --suppress-analytics analyze --no-pub
python3 scripts/with_timeout.py 90 flutter --suppress-analytics test --no-pub --reporter expanded
python3 scripts/test_web_audio.py
python3 scripts/with_timeout.py 180 flutter --suppress-analytics build web --release --no-pub --no-web-resources-cdn
python3 -m http.server 8080 --bind 127.0.0.1 --directory build/web
```

Открыть: <http://127.0.0.1:8080>. Остановка HTTP-сервера: `Ctrl+C`.
Web-ресурсы Flutter включаются в сборку без обращения к CDN.
Локальный bootstrap отключает старый service worker приложения и загружает
актуальный код при перезагрузке, чтобы браузер не показывал предыдущий этап
из офлайн-кэша. Офлайн-режим сейчас не реализуется.

`scripts/with_timeout.py` завершает команду и её дочерние процессы
при превышении лимита и возвращает код 124.

В ограниченной среде Flutter может завершаться с `Operation not permitted`
при записи в `bin/cache` внутри SDK. Это ограничение доступа к кэшу:
запускайте команду с разрешением на использование установленного SDK.
Наличие `bin/cache/lockfile` само по себе нормально. Не удаляйте его
и не завершайте чужие Flutter-процессы без проверки владельца блокировки.

## Структура

```text
lib/main.dart             Точка входа и тема приложения
lib/domain/audit.dart     Оценка, статусы, модель отчёта и текстовый экспорт
lib/demo/                 Вымышленные данные для внутренних тестов расчётов
lib/ui/                   Адаптивный экран редактора и отчёта
lib/services/             HTTP-клиент локального FastAPI
lib/ui/audio_panel.dart   Запись, выбор файла, плеер и состояние распознавания
backend/                  Сервер, бизнес-проверки, промпты и Python-тесты
test/                     Проверки расчётов, данных и поведения интерфейса
docs/business-rules.md    Правила из PDF и ограничения оценки
web/                      Web-оболочка и метаданные
scripts/with_timeout.py   Ограничение длительности проверок
```

## Следующие этапы

Локальный полный цикл проверен, в том числе пользователем на записи 40 минут.
История встреч отложена до следующих версий. Подготовлена отдельная серверная
сборка и конфигурации для проверки MVP компанией Royal Brick:
[deploy/README.md](deploy/README.md). Факт подготовки не означает публикацию:
доступ к VPS, домен и совместимость с существующими службами нужно проверить
перед установкой. Ключ и приватный промпт переносятся отдельно от архива.

При оценке нужно различать «Нет данных» и «Н/П» и не добавлять
отсутствующие в разговоре факты. API-ключи в дальнейшем хранятся только
в серверном окружении. Локальные `.env` исключены из Git.

Royal Brick разворачивается отдельным приложением; службы и данные
проекта «Километры» не изменяются.
