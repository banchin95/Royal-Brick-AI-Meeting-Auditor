# Royal Brick AI Meeting Auditor

Flutter Web MVP для записи и анализа переговоров менеджеров с клиентами.

## Текущий этап

Этап 3: FastAPI и анализ текста через OpenAI, а также учебный деморежим по PDF
заказчика «СИСТЕМНЫЙ ПРОМПТ — АУДИТОР ВСТРЕЧ ROYAL BRICK» (31 страница).

- Три примера: полная встреча, неполная запись, встреча без возражений.
- Редактирование текста и указание ролей участников.
- Девять критериев с весами из PDF, нормированный итог и отдельный охват.
- Различие между нулём, «Нет данных» и «Н/П».
- 13 разделов отчёта, пять проверок цены и точные цитаты с метками.
- Копирование всего отчёта, одного раздела или резюме для CRM.

Переключатель «Демо / ИИ-анализ» позволяет выбрать подготовленный пример
или анализ собственного текста через локальный backend. В режиме ИИ текст
и дополнительный контекст отправляются OpenAI только после нажатия кнопки.
В деморежиме сетевой запрос не выполняется. При изменении входных данных
прежний результат убирается; ошибки API не подменяются демоотчётом.

API-ключ хранится только в `backend/.env.local`, исключённом из Git.
Настройка и запуск сервера описаны в [backend/README.md](backend/README.md).
Вставляйте реплики с подписями `Участник 1:` и `Участник 2:`; назначьте одного
менеджера и одного клиента. Метки времени необязательны. Входные данные
пока хранятся только в памяти вкладки. Запись и распознавание аудио — этап 4.

Исходные разговоры и коммерческие условия примеров вымышлены;
они не являются реальными предложениями Royal Brick. Правила и
границы реализации описаны в [docs/business-rules.md](docs/business-rules.md).

Репозиторий: <https://github.com/banchin95/Royal-Brick-AI-Meeting-Auditor>.
После завершённых шагов изменения коммитятся и отправляются в `origin/master`.

Проверка этапа 2: анализатор Flutter без замечаний, 11 тестов пройдены,
release-сборка Web успешна. В браузере проверены три сценария, охват,
«Нет данных»/«Н/П», копирование CRM-резюме, сброс отчёта после правки
и адаптивное отображение.

Этап 3 проверен отдельно: 24 backend-теста и 15 Flutter-тестов, анализатор
без замечаний, Web-сборка успешна. Реальный вызов OpenAI через интерфейс
вернул 13 разделов для вымышленного короткого диалога. На этом примере
дополнительно уточнены правила оценки неполной записи. Запись заказчика
в этой проверке не использовалась и во внешние сервисы не передавалась.

## Запуск для разработки

Из корневой папки проекта:

```sh
python3 scripts/with_timeout.py 20 flutter --version --suppress-analytics
python3 scripts/with_timeout.py 60 flutter --suppress-analytics pub get --offline
flutter --suppress-analytics run -d chrome --no-pub --web-hostname 127.0.0.1 --web-port 8080
```

Если зависимости ещё не закэшированы, вместо `pub get --offline` выполните
`python3 scripts/with_timeout.py 90 flutter --suppress-analytics pub get`.

Сервер разработки работает до остановки: `q` в терминале или `Ctrl+C`.
Для режима ИИ предварительно запустите backend из отдельного терминала.
Другой адрес backend задаётся через `--dart-define=API_BASE_URL=http://127.0.0.1:8000`
при `flutter run` или `flutter build web`. В этот параметр не передаются ключи.
Если запуск не завершился за две минуты, остановите команду и изучите
вывод; повторять проверку версии в цикле не нужно.

## Сборка и локальный просмотр

```sh
python3 scripts/with_timeout.py 60 flutter --suppress-analytics analyze --no-pub
python3 scripts/with_timeout.py 90 flutter --suppress-analytics test --no-pub --reporter expanded
python3 scripts/with_timeout.py 180 flutter --suppress-analytics build web --release --no-pub --no-web-resources-cdn
python3 -m http.server 8080 --bind 127.0.0.1 --directory build/web
```

Открыть: <http://127.0.0.1:8080>. Остановка HTTP-сервера: `Ctrl+C`.
Web-ресурсы Flutter включаются в сборку без обращения к CDN.
Локальный bootstrap отключает старый service worker приложения и загружает
актуальный код при перезагрузке, чтобы браузер не показывал предыдущий этап
из офлайн-кэша. Офлайн-режим сейчас не реализуется.

`scripts/with_timeout.py` завершает команду и её дочерние процессы
при превышении лимита и возвращает код 124.

В ограниченной среде Flutter может завершаться с `Operation not permitted`
при записи в `bin/cache` внутри SDK. Это ограничение доступа к кэшу:
запускайте команду с разрешением на использование установленного SDK.
Наличие `bin/cache/lockfile` само по себе нормально. Не удаляйте его
и не завершайте чужие Flutter-процессы без проверки владельца блокировки.

## Структура

```text
lib/main.dart             Точка входа и тема приложения
lib/domain/audit.dart     Оценка, статусы, модель отчёта и текстовый экспорт
lib/demo/                 Учебные разговоры и подготовленные разборы
lib/ui/                   Адаптивный экран редактора и отчёта
lib/services/             HTTP-клиент локального FastAPI
backend/                  Сервер, бизнес-проверки, промпты и Python-тесты
test/                     Проверки расчётов, данных и поведения интерфейса
docs/business-rules.md    Правила из PDF и границы деморежима
web/                      Web-оболочка и метаданные
scripts/with_timeout.py   Ограничение длительности проверок
```
