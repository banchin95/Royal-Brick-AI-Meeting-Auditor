# Backend Royal Brick

FastAPI принимает подписанную транскрипцию и роли, вызывает OpenAI Responses API
со структурированным ответом и возвращает 13 разделов отчёта. Баллы и охват
вычисляются сервером; цитаты проверяются по указанной исходной реплике.

## Локальный запуск

Команды выполняются из корня всего проекта. Python 3.12 проверен.
Минимум Python 3.11: он нужен для StrEnum, таймаутов и текущей библиотеки загрузки
файлов. На VPS Ubuntu 22.04 используется отдельный Python 3.12.16 внутри
`/opt/royal-brick`; системный Python не меняется.

```sh
python3 scripts/with_timeout.py 30 python3 -m venv backend/.venv
python3 scripts/with_timeout.py 150 backend/.venv/bin/python -m pip install -r backend/requirements.txt
backend/.venv/bin/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

### Timeweb AI Gateway

Для VPS в России добавлена отдельная конфигурация `AI_PROVIDER=timeweb`.
Ключ AI Gateway хранится в игнорируемом `backend/.env.timeweb.local` как
`TIMEWEB_AI_TOKEN`; ключ управления VPS и ключ OpenAI для этого не подходят.
Запуск: `AI_PROVIDER=timeweb backend/.venv/bin/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --no-access-log`.
Сначала остановить только прежний локальный Royal Brick backend, если этот порт занят.

API имеет фиксированный адрес `https://api.timeweb.ai/v1`.
`TIMEWEB_MODEL` задаёт модель анализа (кандидат `openai/gpt-5.4-mini`),
`TIMEWEB_TRANSCRIPTION_MODEL` — распознавание (`openai/gpt-4o-transcribe`).
Перед реальным запуском проверить доступные идентификаторы через список моделей
для своего ключа. OpenAI и Timeweb используют разные переменные ключей;
при отсутствии токена Timeweb ключ OpenAI не подставляется.

Промпт, строгая схема, проверка исходных цитат, нормирование баллов и охват
одинаковы для обоих провайдеров. Прямые запросы используют `responses.parse`
с `store=False`, без автоматических платных повторов. В Timeweb распознавание
передаёт `language=ru`; экспериментальные голосовые метки отключены.
Каталог моделей и один реальный анализ вымышленного диалога проверены с VPS:
получены все 13 разделов. Распознавание и весь опубликованный цикл проверяются отдельно.

Документация: [подключение Timeweb](https://timeweb.cloud/docs/ai-gateway/manage),
[распознавание](https://timeweb.cloud/docs/ai-gateway/audio-api).

Сервер работает до `Ctrl+C`. Проверка: <http://127.0.0.1:8000/api/health>.
Описание схем: <http://127.0.0.1:8000/docs>. Успешный health означает готовность
локального сервера и наличие ключа, но не подтверждает баланс API.

Секрет хранится в `backend/.env.local` как `OPENAI_API_KEY`. Файл исключён из Git,
ключ не включается во Flutter. Для текущей машины ключ уже сохранён защищённым
потоком настройки. В новом окружении его нужно настроить отдельно; пример
несекретных параметров есть в `.env.example`. Истёкший ключ обновляется на backend.

Модель по умолчанию `gpt-5.4-mini`; меняется серверной переменной `OPENAI_MODEL`.
Параметры: `OPENAI_TIMEOUT_SECONDS=120`, `OPENAI_MAX_OUTPUT_TOKENS=12000`,
`CORS_ORIGINS=http://127.0.0.1:8080,http://localhost:8080`.
Клиент OpenAI обращается только к `https://api.openai.com/v1`, автоматические
повторные платные запросы отключены. Одновременно допускается один запрос
анализа или определения ролей.

## Вход

`POST /api/analyze`, JSON:

```json
{
  "transcript": "[00:00] Участник 1: Здравствуйте! Чем могу помочь?\nУчастник 2: Хочу облицевать цоколь.",
  "participants": [
    {"speaker": 1, "role": "manager"},
    {"speaker": 2, "role": "client"}
  ],
  "is_partial": true,
  "context": "Дата и коммерческие условия не переданы."
}
```

Поддерживаются 2–12 участников: один оцениваемый менеджер, один или несколько
клиентов; остальных можно отметить `other`. Метки времени необязательны;
роли не определяются по номеру голоса. Один запрос возвращает один отчёт
по выбранному оцениваемому менеджеру.
Ограничения: текст до 60000 символов, дополнительный контекст до 16000.

Ответ содержит `source`, `model`, `score`, `stages`, `price`, `sections`.
Заголовок `Cache-Control: no-store` исключает обычное кэширование отчёта.
Входные тексты и результаты не сохраняются в БД или в файлы, содержимое
запросов не логируется. Вызов OpenAI использует `store=False`; это не обещание
нулевого хранения данных на стороне провайдера.

## Предварительное определение участников

`POST /api/prepare-transcript`, JSON `{ "transcript": "..." }`, 30–60000 символов.
Необязательный `reconcile_speakers` (по умолчанию false) разрешает предложить
объединение повторных меток одного человека. Интерфейс передаёт true.
Использует ту же серверную модель, ключ, дедлайн и ограничение параллельности,
что и анализ. Возвращает `source`, `model`, `transcript`, `participants`, `notice`,
`inferred_turns`; каждый участник содержит `speaker`, `role`, `confidence`,
`reason`, `evidence`. Роль может быть `unknown`, уверенность — `high/medium/low`.
Уверенность является оценкой модели, а не калиброванной вероятностью.

При готовых подписях `Участник N:` и false сохраняются исходные номера, слова и время.
При true принимаются до 240 исходных меток: один человек может иметь разные номера
в независимых частях аудио. Модель предлагает сопоставление, а сервер заменяет
только номера в подписях. Все слова, пробелы, порядок и метки времени сохраняются.
Одна исходная метка не может быть разнесена по разным людям. Ответ содержит
`source_speaker_count`, `merged_speakers` и `source_speakers` для каждого участника.
Итоговая нумерация компактная; одинаковая роль не объединяет разных людей.
Неопределённые участники могут остаться отдельными. Лимит 12 подтверждённых
участников для оценки не изменён: его нельзя обходить принудительным объединением.
Для обычного текста сервер выделяет предложения и абзацы, а модель возвращает
только диапазоны их номеров и предполагаемого говорящего. Сервер проверяет
полное покрытие исходника без перестановок, пропусков и повторов и сам собирает
разметку из исходных слов. Цитата берётся из фрагмента этого участника.
Несовместимые диапазоны, роли или цитаты отклоняются с 502; исходник в интерфейсе
остаётся нетронутым. Текст без границ предложений нужно сначала разделить вручную.

Смысловое предположение не подтверждает физическую идентичность голоса.
Особенно неоднозначны короткие ответы, пересказ чужих слов и несколько людей
с одной ролью. Низкая уверенность оставляет роль неопределённой. Метод не
добавляет имена или время и не требует придумать второго человека в монологе.

Пользователь просматривает предложение и применяет его отдельной кнопкой;
можно отменить последнее применение до следующей ручной правки текста.
После аудио этот запрос выполняется автоматически один раз; аудио
повторно не отправляется. Вставленный текст размечается по кнопке
«Определить участников». Лишние переключатели из интерфейса убраны.
Оценка по PDF запускается только после проверки разметки по кнопке анализа.
Неопределённые роли, отсутствие клиента или отсутствие ровно одного выбранного
менеджера блокируют оценку. Контекст сделки не используется для выдумывания реплик.
Результаты не сохраняются сервером; приватные копии контрольного запуска лежат
только в игнорируемой `private-data/` и не включены в Web-сборку.

## Промпт и достоверность

Локально `prompts/royal_brick.local.txt` содержит исходные бизнес-инструкции
заказчика из PDF. Этот файл исключён из Git. При его отсутствии используется
версионируемая реализация правил `prompts/royal_brick.txt`. Перед развёртыванием
нужно отдельно перенести приватный оригинал промпта на сервер.

`response_contract.txt` задаёт JSON-формат, цитаты и границу между инструкциями
и данными. Реплики и дополнительный контекст не могут менять системные правила.
Для итогового анализа сервер делит исходные реплики на точные фрагменты
до 400 символов и передаёт их модели с `quote_id`. Модель возвращает
`GroundedAudit`: в evidence только номера выбранных фрагментов. Текст цитаты,
участник и время подставляются из исходника сервером. Поэтому перефразирование
цитат моделью больше не блокирует весь отчёт. Несуществующие номера отклоняются.
После подстановки цитат выполняются все прежние проверки `GeneratedAudit`:
баллы, охват, состав разделов, последовательность цены и наличие доказательств.
Публичный JSON `/api/analyze` не изменён. Автоматических повторных платных
запросов нет. Это проверяет структуру и происхождение цитат, но не гарантирует
истинность каждого смыслового вывода ИИ.

Этап цены пересчитывается по восьми подкритериям. Подтверждённо неприменимые
подкритерии исключаются и результат нормируется до 10. При неизвестных
подкритериях этап помечается «Нет данных», чтобы не выдавать отсутствие записи
за пропуск действия. Итоговые 100 баллов и охват считаются по доступным этапам.

## Аудио: этап 4

На backend нужны `ffmpeg` и `ffprobe` в PATH; текущая машина уже содержит их.
Аудио передаётся в OpenAI после нажатия «Распознать аудио», автоматической
отправки при выборе файла или записи нет.

- `POST /api/transcriptions`: multipart-поля `file` и `diarize` (true/false, по умолчанию false),
  ответ 202 с ID задачи.
- `GET /api/transcriptions/{id}`: состояния `preparing`, `transcribing`,
  `completed`, `failed`, `cancelled`, результат с репликами и номерами голосов.
- `DELETE /api/transcriptions/{id}`: остановить локальную задачу и ожидание.
  Отмена HTTP-запроса не гарантирует отмену начисления на стороне провайдера.

Один файл до 100 МБ / 60 минут, одна активная задача. FFmpeg создаёт временный
MP3 mono 16 kHz / 48 kbps менее 24 МБ. Оригинал не меняется. WebM без готовой
длительности также поддерживается. Метаданные читаются с лимитом 15 с,
преобразование — 120 с, нарезка — суммарно 120 с, распознавание всех частей вместе — 600 с.
Ожидание результата в интерфейсе ограничено 16 минутами. Временные файлы удаляются
после успеха, ошибки, отмены и штатной остановки сервера. Результаты хранятся
только в памяти до 30 минут; перезапуск backend их удаляет.

`OPENAI_TRANSCRIPTION_MODEL=gpt-4o-transcribe-diarize` даёт анонимные голоса и
метки времени через `diarized_json`, для длинных файлов `chunking_strategy=auto`.
На реальном запросе модель отклонила файл длиннее 1400 секунд (HTTP 400).
При проверке часть в 20 минут превысила дедлайн 480 с. Поэтому backend делит
записи на части до 300 секунд и отправляет не более двух частей одновременно
в пределах общего дедлайна. Метки времени сдвигаются к началу
исходной записи, пропусков и намеренного обрезания нет. На стыках нужно проверить
качество распознавания. Состояние задачи содержит `completed_parts` / `total_parts`.
Номера говорящих уникальны для каждой части: совпадение голоса между частями
автоматически не утверждается. Пользователь объединяет метки через интерфейс
после прослушивания; это заменяет подписи реплик, сохраняя текст и время.
По [документации OpenAI](https://developers.openai.com/api/docs/guides/speech-to-text)
эта специализированная модель совместимости отключается 26 февраля 2027 года.
До этой даты нужно заменить интеграцию разделения голосов или провайдера;
смена одного имени модели не гарантирует совместимость формата.

Основной режим без разделения использует актуальный `OPENAI_PLAIN_TRANSCRIPTION_MODEL=gpt-transcribe`.
Он не выдумывает говорящих: реплики нужно подписать вручную перед анализом.
Интерфейс использует обычное распознавание с последующим определением ролей
по тексту. Переключатель экспериментального разделения голосов убран:
длительные запросы модели совместимости в реальной проверке превышали дедлайн.
`TRANSCRIPTION_TIMEOUT_SECONDS` меняет общий дедлайн OpenAI (по умолчанию 600 с).
Автоматических повторных платных запросов нет.

Все распознанные голоса сначала имеют неизвестные роли. Пользователь слушает
оригинал, исправляет текст и назначает роли. По умолчанию запись помечена как
неполная; если встреча записана целиком, пользователь может снять флаг.
Если модель разделила один голос на несколько меток, объедините их через
«Тот же человек, что…» или исправьте подписи в тексте; список ролей обновится.

## Ошибки и проверки

API возвращает `{ "error": { "code": "...", "message": "..." } }` без текста
исходного запроса и без сообщений SDK, которые могут содержать детали ключа.
Различаются отсутствие ключа, истечение/ошибка доступа, нехватка квоты, лимит
запросов, сеть, таймаут, незавершённый и непрошедший проверку ответ модели.
Ошибки API не подменяются демонстрационным результатом.

```sh
python3 scripts/with_timeout.py 150 backend/.venv/bin/python -m pip install -r backend/requirements-dev.txt
python3 scripts/with_timeout.py 60 backend/.venv/bin/python -m pytest backend/tests -q
```

Тесты используют подмену провайдера и не тратят API-квоту. API слушает только
127.0.0.1; при публикации запросы идут через HTTPS reverse proxy с паролем.
Подготовка отдельного развёртывания описана в [deploy/README.md](../deploy/README.md).
Остальные приложения на VPS не изменяются.

Справочники: [Responses и Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs),
[модель GPT-5.4 Mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini),
[CORS FastAPI](https://fastapi.tiangolo.com/tutorial/cors/).
