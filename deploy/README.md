# Тестовое развёртывание Royal Brick

Отдельное приложение на Ubuntu, без остановки и изменения «Километров».
Это подготовка конфигурации. Сервер, домен и совместимость с существующим
reverse proxy проверяются до применения команд. Общие nginx.conf, firewall,
Docker, Python ОС и службы других проектов не заменяются.

## Схема

- Web собирается на компьютере разработчика, Flutter на VPS не нужен.
- HTTPS-сайт отдаёт Web и проксирует `/api/` на `127.0.0.1:8187`.
- Один процесс API под отдельным пользователем `royal-brick`.
- Отдельная служба `royal-brick.service`: CPU до 60%, память до 768 МБ.
  Эти ограничения нужно сверить со свободными ресурсами до запуска.
- Пароль HTTP Basic защищает и интерфейс, и платные API-запросы.
- Реальные записи, расшифровки, ключ и приватный промпт отсутствуют в архиве.

Для текущего развёртывания выбран Timeweb AI Gateway. Прямой OpenAI с VPS
отклонил проверку региона. В `backend.env.example` указан `AI_PROVIDER=timeweb`;
требуется отдельный токен AI Gateway и проверка доступных моделей. Это не
ключ управления облачными серверами. Временный адрес и основной домен
подключаются только после проверки DNS.

На сервере нужны Python **3.10 или новее**, venv, FFmpeg/ffprobe и работающий
reverse proxy с TLS. Для Python 3.10 используется совместимая реализация
таймаутов `async-timeout`; системный Python менять не требуется.

## Сборка и архив — локально

```sh
python3 scripts/with_timeout.py 180 flutter --suppress-analytics build web --release --no-pub --no-web-resources-cdn --dart-define=API_BASE_URL= --output=build/production-web
python3 scripts/package_release.py --output build/royal-brick-release.tar.gz
```

Пустой `API_BASE_URL` означает текущий адрес сайта по HTTPS. Локальная
`build/web` остаётся отдельной сборкой для разработки. Упаковщик проверяет
наличие файлов и отклоняет сборку с адресом локального backend. В архив
включён только явный список серверных файлов и Web-ресурсы. Повторная упаковка
не перезаписывает старый архив: нужно указать новое имя.

## Проверка VPS — сначала только чтение

Уточнить IP, SSH-пользователя, порт и способ входа. Проверить ОС, Python,
свободную память/диск, загрузку CPU, занятые порты, существующий reverse proxy
и службы «Километров». Проверить доступность OpenAI из региона размещения.
Наличие ключа в `/api/health` не подтверждает доступность OpenAI или баланс.

Порт 8187 должен быть свободен. Если занят, выбрать другой только для Royal
Brick и одинаково изменить `ExecStart` и `proxy_pass`. Внешний порт API
не открывается. Не выполнять `kill`, `restart` или `stop` для других приложений.
Пакеты устанавливать только после просмотра необходимого списка изменений;
не выполнять общее обновление сервера.

## Отдельные пути на сервере

```text
/opt/royal-brick/releases/<release>/     Web, backend и отдельный backend/.venv
/opt/royal-brick/current                 symlink на активный выпуск
/etc/royal-brick/backend.env             серверное окружение, root:root, 600
/etc/royal-brick/royal_brick.local.txt    приватный оригинал, root:royal-brick, 640
/etc/royal-brick/review.htpasswd          пароль тестового доступа, root:www-data, 640
/etc/systemd/system/royal-brick.service  только служба этого проекта
/var/www/royal-brick-acme/               только проверка сертификата этого сайта
```

Релиз и Web-файлы доступны для чтения, но не записи службе API.
Каталоги `/opt/royal-brick`, `releases`, каталоги релиза и Web имеют режим 755
и владельца root:root. `/etc/royal-brick` также root:root, 755: nginx и API
могут пройти к своим файлам, сами секреты защищены указанными выше режимами.
Приватный промпт подключается ссылкой
`<release>/backend/prompts/royal_brick.local.txt` на файл в `/etc/royal-brick/`.
Серверный env загружается systemd через `EnvironmentFile`, не через Web.
Группу nginx (`www-data` в Ubuntu) нужно подтвердить на сервере.

В новый каталог релиза загрузить архив и распаковать.
Распаковка под root использует `--no-same-owner --no-same-permissions`,
чтобы не переносить UID и права с компьютера разработчика. Создать venv внутри
`backend/.venv` и установить `backend/requirements.txt` с ограничением времени,
например 180 секунд через `scripts/with_timeout.py`. Не копировать macOS venv.
Секрет переносится отдельно по SSH после подтверждения серверного пути;
его значение не выводится в терминал и не включается в команды/логи.

## Временный домен и HTTPS

Если своего поддомена нет, после проверки DNS можно использовать имя вида
`royal-brick.<IP-с-дефисами>.sslip.io`. Это DNS-адрес по IP, а сертификат
выпускается отдельно. Он не скрывает IP сервера и зависит от стороннего DNS.

В `nginx-http.conf.template`, `nginx-https.conf.template` и `backend.env.example`
заменить **только** `@@DOMAIN@@` на согласованное DNS-имя. Переменные nginx
`$uri`, `$request_uri`, `$host` не подменять. Файлы с незаменённым шаблоном
не подключать. Не добавлять `default_server` и не изменять другие server-блоки.

Сначала добавить только HTTP-блок с каталогом ACME. После успешного `nginx -t`
сделать `reload` (не `restart`). Получить сертификат через Certbot **webroot**
для одного этого имени; не использовать автоматическое изменение всех
конфигураций через `certbot --nginx` и не останавливать proxy через standalone.
Нужны открытые 80/443; правила firewall менять только после проверки текущих.

Затем подключить HTTPS-блок с паролем. Создание `.htpasswd` делать интерактивно
или через stdin, без пароля в аргументах команды. Не передавать пароль по HTTP.
На HTTP доступна только проверка сертификата и перенаправление на HTTPS.
После `nginx -t` — `reload`. Для существующего Caddy/Traefik использовать его
отдельный маршрут; не устанавливать конкурирующий proxy на занятые 80/443.

Nginx допускает 100-МБ файл с multipart-заголовками, не обрывает анализ на
стандартных 60 секундах и не повторяет платный запрос при ошибке upstream.
После HTTP Basic браузер должен передавать авторизацию при всех `/api/`-запросах;
это нужно проверить на опубликованном сайте перед передачей компании.

## Запуск и проверка

Только после настройки окружения, промпта, venv и ссылки `current` установить
unit, выполнить `systemctl daemon-reload` и `systemctl enable --now royal-brick`.
`daemon-reload` перечитывает unit-файлы, не перезапускает другие службы.

Проверить:

1. Служба Royal Brick активна, API слушает только loopback.
2. `/api/health` возвращает `ai_configured=true`, `audio_tools_ready=true`.
3. HTTPS-сертификат действителен. Без пароля сайт и API возвращают 401.
4. С паролем работают интерфейс, микрофон, загрузка, роли и отчёт.
5. Нет обращений браузера к `127.0.0.1:8000`, mixed content и ошибок CORS.
6. «Километры» отвечают как до установки; их службы и конфигурация не изменены.
7. Продление сертификата настроено существующим certbot timer/cron и проверено.

Журнал только приложения: `journalctl -u royal-brick --since today`.
Не логировать содержимое встреч и ключи. Внешний health тоже защищён паролем.

## Обновление и откат

Новый выпуск устанавливать в новый каталог со своим venv. Сначала проверить
его на свободном loopback-порту, затем атомарно переключить ссылку `current`
и перезапустить **только** `royal-brick`. При сбое вернуть прежнюю ссылку и
перезапустить эту же службу. Старый релиз не удалять до успешной проверки.
Перезапуск прервёт текущую задачу распознавания — обновлять между проверками.

Исходные документы: [nginx proxy](https://nginx.org/en/docs/http/ngx_http_proxy_module.html),
[HTTP Basic](https://docs.nginx.com/nginx/admin-guide/security-controls/configuring-http-basic-authentication/),
[sslip.io / nip.io](https://nip.io/).
